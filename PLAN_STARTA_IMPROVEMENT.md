# Plan: Starta Chatbot Improvement & Migration to Anthropic

## Objective
Improve the Starta chatbot response structure to strictly follow the "4-Layer" rule and migrate the LLM provider from Groq to Anthropic (Cloud) using the provided API key.

## Analysis of Current State

### 1. Response Structure (The "4-Layer" Rule)
The current implementation in `backend-core/app/chat/chat_service.py` and `frontend/app/mobile-ai-analyst/page.tsx` already implements the 4-layer structure:
1.  **Greeting**: Controlled by `GreetingController` and enforced in `chat_service.py`.
2.  **Data Cards**: Generated by intent handlers (`financials_handler.py`, etc.).
3.  **Learning Section**: Generated by `learning_section_generator.py`.
4.  **Follow-up Prompt**: Generated by `follow_up_generator.py`.

**Action Items:**
- Verify `llm_explainer.py` system prompt matches the "Starta AI" persona defined in `complete_implementation_kit.md`.
- Ensure `chat_service.py` allows greetings *only* when appropriate (new session) and strictly enforces the layers.

### 2. LLM Provider (Migration to Anthropic)
The current `backend-core/app/chat/llm_clients.py` supports multiple providers. It prioritizes Anthropic if `ANTHROPIC_API_KEY` is present in settings.
However, `backend-core/app/chat/llm_explainer.py` currently instantiates a `Groq` client directly in `__init__`, which is technical debt.

**Action Items:**
- **Add API Key**: Create `.env` in `backend-core/` with `ANTHROPIC_API_KEY`.
- **Refactor `llm_explainer.py`**: Remove direct Groq dependency. Use `multi_llm` exclusively.
- **Update Model ID**: Ensure `claude-sonnet-4-20250514` (requested by user) is the primary model in `llm_clients.py`.

### 3. "Any Question" / RAG Capability
The user wants the bot to answer "any question" using the DB. The current system uses an `IntentRouter` to specific handlers.
- If a question doesn't match a specific intent (e.g. "Who is the CEO?"), it might fall to `UNKNOWN` or `STOCK_SNAPSHOT`.
- `intent_router.py` has a `COMPANY_PROFILE` intent. I should ensure this handler fetches textual profile data from the DB.
- **Action Item**: Verify `handle_company_profile` (or equivalent) pulls sufficient data.
